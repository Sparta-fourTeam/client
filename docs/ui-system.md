# UI 구조와 편집

UI 개편은 일관성을 우선한다. 화면마다 기능에 필요한 차이는 남기되, 공통 버튼·닫기 아이콘·능력치 행·슬롯은 같은 프리팹을 사용한다. 이전 과정에서 기존 외형을 기록하는 목적은 기능과 누락을 비교하기 위해서이며, 외형을 그대로 유지해야 한다는 제약은 아니다.

## 런타임 조립

`UiHost`는 씬이 소유하는 UI 컨테이너다. `UiComposition`에 등록된 프리팹을 씬 진입 시 한 번 생성하고 씬을 나갈 때 제거한다. 설정의 `Id`는 구성 안에서 고유해야 하며, `ParentPath`는 호스트 아래의 상대 경로다. 배치와 정렬 순서는 설정에서 관리한다.

`UiInstaller`는 VContainer의 `IInstaller`를 구현한다. 로비·전투 스코프는 각 `UiHost`를 생성자로 전달하고 `Install(builder)`에서 UI 레지스트리·공급자·조립 콜백을 설치한다.

생성 순서는 다음과 같다.

1. 비활성 staging 부모 아래에 모든 프리팹을 생성한다.
2. `UiInitialVisibility`로 초기 숨김·표시를 적용한 뒤 `UiRegistry`에 등록하고 `IUiBindable.BindUi`로 화면 사이의 참조를 연결한다.
3. 모든 `HudView.Initialize()`를 호출해 초기 숨김과 버튼 설정을 완료한다.
4. VContainer로 게임 서비스와 메시지 구독을 주입한다.
5. 배치 영역으로 옮겨 활성화한다. 씬 전환 커튼은 `WhenReady`까지 기다린다.

초기화는 한 번만 실행한다. `InitializeView`에서 메시지를 구독하거나 서버를 호출하지 않는다. 구독은 기존 `Construct`에서 수행하며, 초기화 이후에 버퍼 메시지가 재생돼야 한다. 화면 간 참조는 `IUiRegistry.Get<T>()`로 연결하고, 화면 내부의 버튼·텍스트·이미지는 직렬화 참조로 연결한다. 타입이 없거나 두 개 이상이면 조립 오류로 보고한다.

`HudView.Dispose()`는 씬 종료와 부분 생성 실패 모두에서 호출된다. 게임 이벤트 해제와 연출 정리는 `DisposeView`에서 수행한다. Dispose는 중복 호출돼도 한 번만 실행한다.

## Addressables 전환 경계

이번에는 `DirectUiPrefabProvider`가 설정에 지정된 프리팹을 즉시 반환한다. 화면은 로딩 방식이나 경로를 알지 않는다.

`IUiPrefabProvider.LoadAsync`는 취소 토큰과 `UiPrefabLease`를 사용한다. 추후 Addressables 구현은 설정에 로딩 식별자를 추가하고, lease의 해제 콜백에서 로딩 핸들을 반환한다. 생성된 인스턴스는 호스트가 제거하고, 프레임 끝에서 실제 제거된 뒤 lease를 해제한다. 로딩 도중 취소되거나 실패해도 이미 받은 lease와 인스턴스는 정리한다.

Addressables 패키지, 그룹, 번들, 원격 배포 설정은 이번 변경에 포함하지 않는다. 비동기 로딩을 도입할 때는 게임 엔트리 포인트 시작 순서도 확인해야 한다. 현재 직접 참조 구현은 스코프 build callback에서 동기적으로 조립을 끝낸다.

## 프리팹 수정 기준

`Assets/_Project/Prefabs/UI`의 `Lobby`, `Stage`, `Common`, `Hosts` 폴더에서 관리한다. 화면을 편집할 때는 씬 인스턴스 대신 해당 프리팹을 연다. `Assets/_Project/Settings/UI/LobbyUi.asset`과 `StageUi.asset`에서 화면 목록·배치 영역·정렬을 변경한다. 씬에는 `UiHost`와 게임 실행에 필요한 객체만 둔다.

UI 프리팹 49개는 루트와 모든 자식의 `activeSelf`를 활성 상태로 저장한다. 편집할 때 비활성 객체 때문에 화면을 찾기 어려운 문제를 없앤다. 초기 숨김은 루트의 `UiInitialVisibility`의 `Hidden On Start`에 지정하고, 공통 요소의 숨김 기본값을 해당 사용처에서 표시해야 하면 `Shown On Start`에 지정한다. 런타임 초기화는 한 번만 적용하며 이후 탭·잠금·선택·팝업 표시 상태는 각 View가 변경한다. 새 객체는 활성으로 편집하며, 시작부터 숨겨야 한다면 이 설정에 추가한다.

독립 화면과 팝업은 다른 화면 프리팹 안에 넣지 않는다. `MissionDetailsPopup`, `MissionRewardInfoPopup`은 임무 화면에서 분리해 로비 팝업 레이어의 동료 UI로 조립한다. `SkillHud`, `StageControls`는 전투 HUD에서 분리하며, 호스트의 `HudLayer/SafeArea` 아래에서 상태 HUD와 함께 배치한다. 로비 구성은 18개, 전투 구성은 8개다. 버튼·슬롯·행·효과 같은 내부 요소의 중첩 프리팹은 재사용을 위해 유지한다. 화면 간 참조는 `IUiBindable`과 `UiRegistry`로 연결한다.

- 기본 프리팹: 모든 사용처에 반영돼야 하는 모양과 동작.
- Variant: 역할은 같지만 의도적으로 다른 모양이 필요한 경우.
- 부모 레이아웃: 배치·순서·화면별 공간.
- 바인딩: 문구·아이콘·수치·잠금 등 데이터에 따라 달라지는 표시.

비슷한 외형만 보고 서로 다른 동작의 요소를 같은 프리팹으로 묶지 않는다. 같은 계층에 같은 이름이 두 개 있으면 역할을 확인해 분리하거나 불필요한 것을 제거한다. 비활성이라는 이유만으로 템플릿이나 상태별 표시를 삭제하지 않는다.

프리팹 활성 저장을 맞추기 위해 쓰이지 않는 장식을 초기 숨김 목록에 남기지 않는다. 로비 하단 메뉴의 `Art_Glyph` 3개와 임무 화면의 `Art_Border`·`Art_Border_2`·`Art_Glyph` 6개는 초기화 후 다시 표시하는 동작이나 참조가 없어 프리팹에서 제거했다. 상태 갱신에 연결되지 않은 Shop·Gacha·NekoNinja·Workshop·Barrier 탭의 알림 점 5개도 각 화면에서 제거했다. 공통 탭 템플릿과 실제 강화·수령 상태에 연결된 알림 점은 유지한다. 잠금·선택·수령 가능·보스·카드 조건·팝업 등 실제 상태로 바뀌는 표시는 보존한다. 프리팹과 인게임의 차이는 데이터에 따른 문구·아이콘·수치, 초기 화면 상태와 Safe Area·카메라 배치에서도 생긴다.

이미지로 교체된 텍스트·기호는 직렬화 참조, UnityEvent, 애니메이션 바인딩을 확인한 뒤 제거한다. 장식 이미지는 Raycast Target을 사용하지 않으며, 입력 차단용 이미지는 역할이 드러나는 이름을 사용한다.

## 강화·수령 알림

`Common/NotificationBadge.prefab`은 공통 알림 점이다. 프리팹 객체는 활성 상태를 유지하고 런타임에서는 `CanvasGroup.alpha`로 표시한다. 이미지와 CanvasGroup은 터치를 가로채지 않는다.

`LobbyNotificationView`는 프로필 변경을 구독해 장비·스킬의 각 슬롯, 해당 하위 탭, 하단 캐릭터·스킬 NavTab을 같은 규칙으로 갱신한다. 해금됐고 최대 레벨이 아니며 강화 데이터가 있고, 현재 골드와 재료로 실제 강화 가능한 경우만 표시한다. 강화 버튼과 알림은 `LobbyAvailability.CanUpgrade`를 함께 사용한다. 화면이 닫혀 있어도 프로필 변경은 상위·하위 표시 모두에 반영한다.

홈 NavTab과 임무 입장 버튼은 **어느 관문에든** 미수령 달성 보상이 남아 있으면 표시한다. 현재 최고 관문만 검사하지 않으며, 남은 보상을 모두 수령했을 때 꺼진다. 상점·뽑기 및 미구현 하위 탭에는 알림 조건을 연결하지 않는다. 표시한다고 보상을 자동 수령하거나 재료를 소비하지 않는다.

## 강화 확인과 일괄 강화

스킬·장비의 강화 버튼은 `UpgradeConfirmPopup`을 연다. 별도 프리팹으로 로비의 `NavUI/Overlays`에 등록돼 있어 기존 강화 팝업 안에 중첩하지 않는다. 이름, 현재·목표 레벨, 강화 횟수, 엽전·재료의 총소모량과 취소·확인 버튼을 보여준다. 취소하거나 닫으면 구매 요청을 보내지 않는다.

장비의 **일괄 강화**는 선택한 장비를 현재 재화로 가능한 만큼 연속 강화한다. `UpgradePurchasePlan`이 각 다음 레벨의 개별 비용을 더해 가능한 횟수를 계산한다. 확인한 횟수·비용 범위 안에서만 한 단계씩 구매하며, 최대 레벨이나 재화 부족에 도달하면 추가로 요청하지 않는다. 확인 전에 레벨·재화가 바뀌면 새 비용을 표시하고 다시 확인받는다.

처리 중에는 확인·취소·닫기를 막고 진행 횟수를 표시한다. 응답마다 프로필을 적용해 강화 화면과 알림을 갱신한다. 중간 요청이 실패하면 이미 성공한 강화를 유지하고 완료 횟수와 남은 비용을 보여준다. 다시 확인해야 남은 강화를 실행한다. 화면이 삭제되면 새로운 구매 요청을 이어가지 않는다.

## 에디터 도구

`Tools > Project Nova > UI Workspace`를 연다. 로비·전투·공통 요소를 선택하고 이름으로 검색한다. **프리팹 편집**은 선택한 프리팹을 열고, **화면 구성 선택**은 화면 목록·배치 설정을 Inspector에서 연다.

미리보기는 선택한 화면을 호스트의 레이어·정렬 순서 안에 놓는다. 로비의 배경·상단·하단 메뉴와 전투 HUD도 함께 표시한다. 6개 화면 크기, 9:16 카메라 영역, Safe Area, 해당 화면에 필요한 잠금·최대 레벨·결과 상태를 지원한다. 수치와 아이콘은 프리팹 기본값이다. **PNG 저장**으로 현재 화면만 출력한다. 실제 데이터·터치·기기 동작은 Play Mode와 Unity Device Simulator에서 확인한다. 편집 미리보기는 재생 중 실행하지 않는다.

**UI 문제 검사**는 참조 누락, Missing Script, 중복 이름, 배치 영역 누락, 장식 이미지의 터치 차단, 이미지로 대체된 미참조 문구를 찾는다. 결과를 누르면 해당 프리팹과 객체를 선택한다. 상태 표시나 애니메이션이 사용하는 비활성 문구는 잔재로 보고하지 않는다. 에셋 변경 뒤 검사를 다시 실행한다.

일회성 이전·통합 도구와 별도 HUD 미리보기·일괄 PNG 출력·테스트 실행 메뉴는 삭제했다. 테스트는 Unity의 `Window > General > Test Runner`에서 실행한다. 전체 도구의 용도와 삭제 기준은 [에디터 도구](editor-tools.md)를 참고한다.

시트 조각을 감싼 `LayeredAssets`의 제작용 프리팹 117개는 참조가 없어 폴더째 제거했다. 시트 번호별 이름을 새 이름으로 옮기는 대신, 실제 재사용하는 프리팹은 `Common`, `Lobby`, `Stage`에 둔다. `Generated/LayeredSheets`의 Sprite와 사용 중인 화면·공통 요소는 유지한다.

## 검증 결과

이전된 에셋과 새 에디터 도구로 EditMode 테스트 836개가 통과했다. 런타임 통합 테스트 6개는 실제 Play Mode에서 Boot → Loading → Lobby → Stage를 실행한다. 로비·전투 두 번 왕복, 게임 화면 버튼의 포인터 레이캐스트·탭 이동·임무 상세·입장·배속·카드 선택·방벽 피해와 패배, Playtest의 제출 실패·재시도, 첫 스테이지 20웨이브 클리어·진행 저장, 씬 전환 중 재생 종료, 닫힌 화면의 강화·수령 알림 전파와 표시된 탭의 실제 클릭, 강화 확인·취소와 장비 일괄 강화의 정확한 재화 차감을 확인한다. 적 진행은 실제 스폰과 피해 경로를 빠르게 실행한다. 세이브는 임시 파일로 분리하고 배속·재생 시작 씬 설정은 복원한다. 자세한 조건은 [런타임 UI 테스트](ui-runtime-tests.md)를 참고한다. 조립 테스트는 실제 두 호스트의 프리팹 참조·화면 연결·초기화와 로딩 실패·취소·해제 경로를 검사한다.

현재 UI 문제 검사 결과는 오류·검토 모두 0개다. 이전 검사에서 비활성 문구로 표시됐던 12개 `CardSlot/FormHints/*/Blocked`는 `FormHintIconView._blockedMark`가 사용하는 상태 표시이므로 유지하고, 새 검사에서는 잘못된 경고를 내지 않는다. Portrait 위의 미참조 `Placeholder` 문구는 제거했다. 전체 테스트 결과와 구성 미리보기는 `Logs/ToolChecks`에 보관한다.

재화 UI는 버퍼 구독의 미발행 기본값을 잔액으로 취급하지 않는다. 첫 실제 잔액은 즉시 표시하며 이후 실제 잔액 변경에만 카운트 효과를 적용한다. `WalletViewTests`는 빈 버퍼 뒤의 초기 잔액(0 포함)과 증가·차감 효과를 검증한다.
