# 테스트 유지 기준

EditMode 테스트는 동작이 깨졌을 때 실제 문제가 되는 경로에 집중한다.

- 전투 진행: 웨이브 전환, 클리어·실패의 단일 판정, 일시정지, 카드 선택과 제출 재시도.
- 전투 계산: 적중·범위·상태이상·자식 스킬·강화 조합, 풀 재사용과 정리.
- 데이터 보존: 저장 재로딩, 재화 차감·보상, 중복 요청, 거절·오버플로 시 부분 변경 방지.
- API 계약: 요청 주소·본문·인증, 응답 검증, 오류 분류와 취소.
- 화면 동작: 게이지 진행, 표시 조건, 연속 입력, 화면 영역 계산, 재사용 시 표시 복원.
- 에셋 연결: 전체 카탈로그의 프리팹·아이콘 연결과 실제 스킬 피해 발생.

단순 getter·기본값·컬렉션 래퍼, 같은 경로를 더 짧게 재검증하는 테스트는 추가하지 않는다. 여러 검사가 같은 준비와 실행을 공유하면 대표 동작 테스트에 필요한 assertion을 합친다. 독립적인 경계 조건과 실패 경로는 유지한다.

현재 밸런스 값, 캐릭터 수, 미구현 카드 수, 문구를 그대로 복사한 기대값은 유지하지 않는다. 카드 효과 전체를 복제한 골든 파일도 사용하지 않는다. 스킬 효과별 계산·스냅샷 독립성 테스트와 실제 전투·카드 적용 검증으로 확인한다. 밸런스 변경 후에는 Skill Sandbox로 연출을 확인한다.

삭제한 단순 투사체 기하 검사는 실제 고속 투사체의 적중·빗나감 검사로, 개별 스킬 프리팹 존재 검사는 `SkillCatalogSafetyNetTests`의 전체 카탈로그 검사로 대체한다. 몬스터 프리팹 연결과 애니메이터는 `EnemyPrefabMonsterLinkTests` 한 곳에서 전체 몬스터를 검사한다.

## 실행

```sh
unity test . --mode EditMode --output /private/tmp/nova-editmode-tests.xml --timeout 1200
```

반드시 정리한 브랜치의 worktree에서 실행한다. 결과 XML에서 실패가 없는지와 예상한 테스트가 발견됐는지 함께 확인한다.
