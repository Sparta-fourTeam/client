# 런타임 UI 테스트

`UiRuntimeFlowTests`는 Editor용 테스트 어셈블리 안에서 `EnterPlayMode`·`ExitPlayMode`를 사용해 실제 게임 씬과 DI 서비스, 프리팹 UI를 실행한다. 검증 환경은 Unity 6000.6.3f1의 Editor Play Mode, Local 백엔드, Android 빌드 타깃이다.

| 시나리오 | 확인하는 동작 |
|---|---|
| 로비·전투 왕복 | Boot → Loading → Lobby, 팝업 연결, Stage → Lobby 두 번 왕복, 일시정지·재개·포기, 제출 실패와 재시도, UI 호스트 중복 방지 |
| 게임 화면 입력·패배 | 캐릭터·스킬·홈 탭의 배타적 표시, 임무 상세 열기·닫기와 입장, 2배속·일시정지·재개, 카드 선택과 빌드 로그, 방벽 HP 표시, 패배 TIP 닫기와 로비 복귀 |
| 20웨이브 클리어 | 첫 스테이지의 원본 웨이브 데이터 전체 진행, Playtest 카드 선택, 최종 클리어 결과, 다음 관문 해금과 저장, 로비의 시간 배속 복원 |
| 강화 확인·일괄 강화 | 실제 장비 일괄 강화 버튼 → 소모 재화 확인 → 취소 시 유지 → 확인 후 정확한 레벨·골드·재료 차감, 스킬 확인 후 1회 강화 |
| 강화·수령 알림 | 닫힌 화면의 슬롯·하위 탭·NavTab과 임무 버튼 표시, 재화·수령 상태 변경 후 갱신, 알림이 표시된 버튼의 실제 클릭 |
| 전환 중 재생 종료 | 커튼이 닫히는 중 재생을 종료해 삭제된 CanvasGroup이나 루트 스코프를 계속 참조하지 않는지 검사 |

게임 버튼은 화면 좌표에서 `EventSystem.RaycastAll`을 실행하고 최상위 클릭 대상이 해당 버튼인지 확인한 뒤 포인터 이벤트를 전달한다. 다른 이미지나 패널이 버튼을 가로막으면 실패한다. Playtest 버튼은 포커스와 UI Toolkit 제출 이벤트를 사용한다.

웨이브 검증은 실제 EnemySpawner의 시간 진행과 Enemy의 피해 처리를 빠르게 실행한다. 카드·클리어·패배 메시지를 테스트에서 직접 발행하지 않는다. 이 조건은 UI와 진행 흐름을 검증하기 위한 것으로 전투 난이도를 측정하지 않는다.

세이브 경로는 부팅 전에 임시 파일로 교체한다. 시작 씬 강제 지정과 배속 설정은 종료 시 복원하고, 테스트 파일은 삭제한다. 실행은 원본 에셋 전체를 복사한 별도 작업 디렉터리에서 수행했다.

## 발견하고 수정한 문제

- 로비 호스트의 Canvas 이름과 `LobbyUi`의 `NavUI/...` 경로 불일치: 호스트 이름을 구성 경로에 맞춰 로비 조립을 복구했다.
- 재생 종료 뒤 커튼 비동기 연출의 삭제된 CanvasGroup 접근: 연출 중 객체 수명을 확인하고, 루트가 삭제되면 추가 씬 로딩을 중단한다. 커튼 프리팹은 활성으로 저장하지만 런타임 초기 상태에서 숨긴다. 전환 요청은 CanvasGroup을 확보한 뒤 커튼을 켠다.


강화·수령 알림 시나리오는 화면을 닫은 상태에서 골드·재료·보상 수령 스냅샷을 변경하고, 장비·스킬 슬롯 → 하위 탭 → 하단 NavTab의 표시와 임무 버튼을 확인한다. 표시가 켜진 상태에서도 실제 탭 버튼의 레이캐스트·클릭이 정상 동작하는지 검사한다. 골드·재료 부족, 잠금, 최대 레벨, 강화 데이터 없음, 과거 관문의 미수령 보상은 별도 규칙 테스트에서도 검증한다.

## 실행 결과와 재실행

2026-10-11: 런타임 시나리오 6개와 이를 포함한 전체 테스트 836개 통과. 실패·건너뜀은 0개다. 전체 회귀 테스트 결과와 개별 런타임 결과는 `Logs/RuntimeChecks`에 보관한다.

Unity의 `Window > General > Test Runner`에서 EditMode 탭의 `Game.Tests.UiRuntimeFlowTests`를 선택해 실행한다. 테스트 어셈블리는 Editor 전용이지만 각 시나리오는 실제 Play Mode로 들어가 검증한다.

`UpgradeConfirmationTests`는 레벨별 총비용·강화 횟수, 취소 후 늦은 확인, 연타·진행 중 취소, 확인 전 변경된 비용 재확인, 중간 실패 후 성공분 유지와 재시도를 검사한다. `UpgradeConfirmPopup` 미리보기는 테이블의 후드 0→2레벨 예시 비용이며 구매 API를 호출하지 않는다.

에디터 도구·Scene View와 Game View의 해상도가 다를 수 있으므로 게임 버튼 테스트는 Game View에 포커스를 맞추고 Canvas 렌더 시점에 화면 크기가 일치할 때 실제 EventSystem 레이캐스트를 검사한다. 에디터 업데이트 단계에서 Scene View 크기가 남아 있으면 정상 버튼을 화면 밖으로 오인할 수 있다.
