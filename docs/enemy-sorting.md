# 그리기 순서 (정렬 레이어와 sortingOrder)

전투 화면에서 무엇이 무엇 위에 그려지는지 정리한다. 몬스터끼리의 앞뒤를 정하는 깊이 정렬도 함께 다룬다. 값은 코드와 프리팹이 원본이고, 이 문서는 전체 배치를 한눈에 보고 새 오브젝트의 순서를 정할 때 참고하기 위한 것이다.

## 정렬 레이어

| 레이어 | 쓰는 곳 |
| --- | --- |
| `Default` | 월드에 있는 모든 것: 배경, 몬스터, 벽, 플레이어, 스킬·투사체·이펙트, 적 HP 바, 데미지 숫자 |
| `UI` | 전투 HUD 캔버스(`HudCanvas` 20, `StageUiHost` 20·30). 항상 `Default` 위에 그려진다(#249 / PR #260) |

정렬 레이어가 같으면 `sortingOrder`가 큰 쪽이 앞이다. 레이어와 순서가 모두 같으면 Unity가 그리는 순서를 보장하지 않는다. 겹치는 오브젝트끼리는 순서가 같지 않게 해야 한다.

## Default 레이어 순서 배치

뒤에서 앞 순서다.

| 순서 | 대상 | 정하는 곳 |
| --- | --- | --- |
| -500 | 배경 | Stage 씬 |
| -450 ~ -410 | **바닥 구간**: 몬스터 뒤에 깔리는 연출. `FrostPrison`(-440, -436), `ElectricField`(-430, -429), `Log`(그룹 -425), `BurningRootWave`·`LargeRootWave`(-427, -425, 장판 위), `Fx_GroundSlam`·`Fx_SonicWave`(-420) | 각 프리팹 |
| **-402 ~ -10** | **몬스터 몸** (비주얼 `SortingGroup`) | `EnemyDepthSorter` (아래 "몬스터 깊이 정렬") |
| 몸 + 1 | 몬스터 상태이상 이펙트 (`Resources/VFX/EnemyStatuses`) | `EnemyStatusEffects` |
| 몸 - 1 | 몬스터 사망 이펙트 (`Resources/VFX/EnemyDeath`) | `Enemy` 사망 처리. 죽는 순간의 몸 순서로 정한다 |
| -5 | 벽 (`Wall`). 몬스터 앞, 스킬 뒤 | 프리팹 |
| 0 ~ 30 | 스킬·폭발 이펙트 (`Resources/VFX/*Explosion`, `Prefabs/Skills/*`). 프리팹마다 루트 `SortingGroup` 하나로 묶고, 순서는 안쪽 파츠의 가장 큰 값이다. 안쪽 파츠 순서(-1~16)는 그룹 안에서만 비교한다 | 각 프리팹 |
| 35 | 적 투사체 (`Slime_Projectile`). 스킬·폭발(0 ~ 30)과 동률 없이 그 위, 플레이어(40) 아래 | 프리팹 |
| 40 | 플레이어 (`Player_Animated`). 루트 `SortingGroup`으로 몸통·그림자·오브를 묶어 한 번에 비교한다 | 프리팹 |
| 90 | 스킬 범위 표시 (`SkillRangeIndicator`) | 프리팹 |
| 100 ~ 103 | 적 HP 바 (`Resources/UI/EnemyHpBar`) | 프리팹 |
| 198 ~ 201 | 데미지 숫자 (`Resources/UI/DamagePopup`) | 프리팹 |
| 300 | 화면 전환 막 (`TransitionCurtain`) | 프리팹 |

`UiClickFeedback`(32000)은 Screen Space Overlay 캔버스라 월드 순서와 따로 맨 위에 그려진다.

몬스터 프리팹 안의 파츠(6~40)와 그림자(`EnemyShadow`, -1000)는 몬스터 비주얼 `SortingGroup` **안**의 순서다. 그룹 안에서만 비교되므로 위 표와 섞이지 않는다.

### 새 오브젝트의 순서를 정할 때

- **몬스터보다 앞**에 보여야 하면 -9 이상을 쓴다. 투사체·스킬 이펙트는 보통 0 이상이다.
- **몬스터보다 뒤, 배경보다 앞**(바닥 장판, 바닥에서 솟는 연출, 나무뿌리)에 보여야 하면 바닥 구간 -450 ~ -410을 쓴다. 사망 이펙트가 -403까지 내려가므로 -409 ~ -403은 비워 둔다.
- -402 ~ -10은 몬스터와 몬스터 이펙트 전용이다. 다른 오브젝트가 쓰면 몬스터 몇 마리와만 앞뒤가 뒤섞인다.
- 구간 값은 `SortingBands`(Core/Combat)가 원본이다. **Tools → Project Nova → Validate Sorting Orders**가 바닥 연출 프리팹이 바닥 구간 안에 있는지, 다른 프리팹이 몬스터 구간을 침범하지 않는지 검사한다. 새 바닥 연출은 검증 메뉴의 `GroundPrefabs` 목록에도 추가한다.
- 여러 파츠로 된 이펙트는 루트에 `SortingGroup`을 두어 바깥과 한 번만 비교되게 한다. 그룹이 없으면 두 이펙트의 파츠가 서로 섞인다. 검증 메뉴가 `Prefabs/Skills`와 `Resources/VFX`의 루트 `SortingGroup`을 확인한다.
- 같은 순서끼리는 앞뒤가 보장되지 않는다. 겹칠 수 있는 서로 다른 종류는 다른 값을 쓴다.

## 몬스터 깊이 정렬

화면 아래쪽(발끝이 낮은) 몬스터가 앞에 그려진다.

### 구조

| 대상 | 역할 |
| --- | --- |
| `EnemyDepthSort` (적마다) | 발끝 높이(`FootY`)를 제공하고 받은 순서를 비주얼 `SortingGroup`에 적용한다. 발끝은 `Bind` 때 스프라이트 아래쪽 끝(그림자 제외, `VisualBounds.BottomY`)으로 한 번 재고, 이후에는 위치만 본다 |
| `EnemyDepthSorter` (전역, static) | 살아 있는 적 전체를 발끝 높이순으로 한 줄로 세워 순서를 정한다 |
| `EnemyStatusEffects` | 몸 순서 + 1을 그대로 따른다 |

`EnemyDepthSorter` 동작:

1. 줄의 0번이 맨 앞(발끝이 가장 낮은 적)이다. 지난 프레임의 줄을 그대로 둔다.
2. 앞 적보다 발끝이 **`Hysteresis`(0.03) 넘게 낮아졌을 때만** 앞으로 보낸다(삽입 정렬). 거의 정렬된 줄이라 한 번 훑는 수준으로 끝난다.
3. 순서 = `FrontOrder(-10) - 줄번호 × Spacing(3)`이고 `BackOrder(-402)`에서 자른다. 3칸 간격은 몸 ±1을 쓰는 상태이상·사망 이펙트가 이웃 적과 겹치지 않게 하기 위해서다.
4. 새 적은 히스테리시스 없이 높이에 맞는 자리에 넣는다. 높이가 같으면 먼저 있던 적이 앞이다.
5. 순서가 **바뀐 적에게만** 쓴다. 정렬은 프레임마다 한 번(첫 `EnemyDepthSort.LateUpdate`)만 하고, GC 할당은 없다.
6. `EnemyDepthSort`는 `[DefaultExecutionOrder(-100)]`이라 상태이상 이펙트보다 먼저 돈다. 그래서 상태이상은 같은 프레임에 정해진 몸 순서를 읽는다.

static으로 만든 이유는 Sandbox와 EditMode 테스트에서도 DI 연결 없이 동작하게 하기 위해서다. 파괴된 적은 정렬할 때 걸러낸다. `RuntimeInitializeOnLoadMethod`로 초기화하므로 도메인 리로드를 꺼도 이전 플레이의 줄이 남지 않는다.

### 한계

- 순서 칸이 -402 ~ -10이고 3칸 간격이라 **131마리까지** 순서가 모두 다르다. 그 뒤쪽 적들은 -402에서 같은 순서가 된다. 실제 스테이지는 30마리 안팎이다. 더 필요하면 배경(-500)을 더 뒤로 빼고 `BackOrder`를 낮춘다.
- 맨 앞 적이 죽으면 그 뒤쪽 적들의 줄 번호가 한 칸씩 당겨진다. 그래서 그 프레임에 순서를 한꺼번에 다시 쓴다(아래 측정의 "쓰기 몰림").

### 왜 이렇게 바꿨나 (#244 → PR #323)

- #244(PR #263)는 적마다 `순서 = -2 - round((발끝y + 10) / 0.05)`로 높이를 0.05 칸으로 나눠 정했다.
- 몬스터가 벽 앞에 멈추면 발끝 높이가 거의 같아져서 **겹친 적끼리 순서가 같아졌다**. 그리는 순서가 보장되지 않아 앞뒤가 깜빡였다(버벅여 보였다).
- 칸을 0.01로 줄여도 동률이 44% 남았다. 높이가 사실상 같아서 칸을 줄이는 것으로는 해결되지 않는다.
- 같은 칸 안에서 고정 순번으로 동률을 깨는 방식도 비교했다. 칸 경계에서 "칸 비교"와 "순번 비교"가 번갈아 걸려 떨림이 오히려 늘었다.
- 상태이상 이펙트는 발끝을 따로 재서 순서를 다시 계산했다. 그래서 몸 + 1과 어긋났다(2.2%).

## 측정 결과

2026-10-12, 에디터 Play Mode(Mono)에서 쟀다. 레벨업 카드는 자동으로 골랐다. 스트레스 조건은 3스테이지를 메모리에서 복제해 스폰 간격 0.3~0.45초, 웨이브당 62마리로 만든 임시 스테이지다.

### 방식 비교 (스트레스 조건, 150초, 최대 약 420마리, 같은 프레임에서 동시에 계산)

| 방식 | 겹친 적 동률 | 10프레임 안 앞뒤 재전환(떨림) |
| --- | --- | --- |
| #244 방식 (0.05 칸) | 56% | 5 |
| 0.01 칸 | 44% | 402 |
| 0.05 칸 + 고정 순번 | 0 | 4,629 |
| 연속 높이 + 고정 순번 | 0 | 729 |
| **한 줄 정렬 + 히스테리시스 0.03 (채택)** | **0** | **1** |

### 적용 전후

| 항목 | 1스테이지 전 → 후 | 스트레스 전 → 후 |
| --- | --- | --- |
| 겹친 적 동률 | 6.6% → **0%** | 56% → 20%* |
| 떨림 | 1 → **0** | 5 → **0** |
| 상태이상 순서 ≠ 몸 + 1 | 2.2% → **0%** | 0% → 0.005% |
| 몸 순서 쓰기 / 프레임 | 약 0.7 → **0.09** | — → 1.3 |
| 상태이상 순서 쓰기 / 프레임 | 적 수만큼 매 프레임(약 5.4) → **0.09** | — → 1.3 |
| 정렬 시간 / 프레임 | — → 평균 2.8µs, 최대 62µs | — → 평균 86µs, 최대 388µs |
| 쓰기 20회 초과 프레임 | — → 8 / 7,866 (최대 30) | — → 136 / 7,480 (최대 232) |
| GC 할당 | 0 → 0 | 0 → 0 |

\* 수용량을 넘은 뒤쪽 적들이 같은 순서가 된 것이다(위 "한계"). 이 측정은 `FrontOrder`가 -2일 때 했다. 지금 값 -10에서는 수용량이 134마리에서 131마리로 줄어든다.

### 개선 후보 (적용 안 함)

- 정렬 전에 발끝 값을 배열에 한 번만 담으면, 비교마다 `transform.position`을 읽지 않아도 된다. 순회 시간이 절반 정도로 줄어들 것으로 예상한다.
- 앞뒤 이웃 사이에 여유가 있으면 기존 순서를 유지하게 하면 쓰기 몰림이 줄어든다. 단, 이웃 간격 3칸은 지켜야 한다.

## 측정 방법

- 렌더 직전 콜백(`RenderPipelineManager.beginCameraRendering`)에서 매 프레임 `EnemyDepthSort`가 붙은 적의 비주얼 범위와 순서를 모은다. 게임 상태는 바꾸지 않는다.
  - 범위가 겹치는 쌍에서 순서가 같으면 "동률"이다.
  - 순서의 부호가 바뀌면 "앞뒤 바뀜"이고, 바뀐 지 10프레임 안에 다시 바뀌면 "떨림"이다.
  - 같은 적의 두 번째 `SortingGroup`(상태이상 이펙트)이 몸 + 1인지 본다.
  - 정렬 시간은 같은 프레임에 `EnemyDepthSorter.Sort()`를 한 번 더 불러 잰다. 이미 정렬된 상태라 쓰기는 생기지 않는다.
- 몬스터가 쌓이도록 레벨업 카드를 자동으로 고르고 120초 이상 진행한다.
- 프로브 자체가 O(n²)이라 수백 마리일 때는 프레임 시간이 늘어난다. FPS는 프로브를 끄고 Profiler로 잰다.
- 세이브는 측정 전에 백업하고 끝나면 되돌린다.
