# 인술 요구사항 기준

[카드별 대응표](requirements.md)와 [구조화 데이터](requirements.json)는 요구사항 문서다. 런타임에서 직접 읽는 테이블이 아니다. 실행 데이터는 아직 `Assets/_Project/Resources/MockData/Weapons.json`이다.

15종·168행을 [추가 자료 원문](ninjutsu-source-additional.txt) 및 [최초 자료 원문](ninjutsu-source-initial.txt)의 줄 번호에 연결했다. 기존 실행 강화 9개는 각각 하나의 문서 행에 매핑했다. 제안 문서 ID는 기존 실행 ID를 대체하지 않는다.

## 확정된 결정

- 해금 조건의 인술 레벨은 로비 영구 인술 레벨이다.
- 최대 등장 횟수는 선택 성공 시에만 사용한다. 미선택 제시와 적용 실패는 차감하지 않는다.
- 최대 레벨은 **최초 습득을 제외한 전투 강화 횟수 상한**이다. 예를 들어 쿠나이는 습득 이후 최대 15회의 성공한 강화를 허용한다. 기존 표시 레벨이 1부터 시작한다면 표시값과 강화 횟수를 분리한다.

- (+)/일반은 같은 카드이며 최대 등장 횟수를 공유한다. [제공 각주](source-footnotes.md)에 따라 전환 레벨과 피해 보정은 카드별로 5·9·17레벨이며, 연발 쿠나이는 공격력 +10%로 바뀐다. 각주 없는 디버프는 자동 제거하지 않는다.
- 두 인술의 증폭/연마 선택은 양쪽 인술의 습득 수를 증가시킨다.
- 쿠나이 난사는 확산과 합쳐 보조 쿠나이 총 6개를 발사한다. 히스이 비기는 예외적으로 태풍 레벨을 참조한다.

## 보류된 결정

- 두 자료에서 다른 선행조건·피해 감소·등장 횟수.
- 백분율 효과의 합연산/곱연산, 기본 수치, 반복 간격.
- 영구 성장 ID, 캐릭터 기본 강화의 횟수 사용, 계열 증폭의 실제 양쪽 상태 갱신 및 실행 연결.
- 동명·유사 명칭, 캐릭터 이름 불일치와 비취 폭풍의 성장 인술 참조.

`source-defined`는 자료에 명시된 행이라는 뜻이다. 실행 완료나 모든 정책의 확정을 뜻하지 않는다. `hold` 행은 사유를 해결하기 전 활성 데이터로 자동 변환하지 않는다. 기존 실행 활성 행 중에도 보류 항목이 있어 검토가 필요하다.

원문의 전력망 충전 반복 표기는 후속 과부하 연결을 설명한 것으로 정리했고, 비기 설명의 반복 문장은 별도 카드로 중복 생성하지 않았다. 삼각 얼음창은 일반 얼음창을 삼각으로 바꾸는 분열이 아니라 삼각→일반→소형의 분열 순서를 보존한다.

검증: 저장소 루트에서 `python3 docs/ninjutsu/validate_requirements.py`. ID·참조·횟수·원문 위치·실행 매핑·선행조건 순환 및 얼음창의 단방향 제한을 확인한다. Unity 전투 효과와 최종 규칙을 검증하는 테스트는 별도로 필요하다.

최초 분류 자료에는 여우불이 있지만 추가 15종 목록에는 없다. 여우불은 효과 자료가 없어 이번 카드 대응표 범위에 추가하지 않았다. 원문 분류에 명시된 속성·대상·지속 여부는 보존하되, 예시만 있는 시전 형태를 모든 인술에 임의 확장하지 않는다.

## 실행 연결 진행

쿠나이 일제 사격·연발 쿠나이·연속 벼락의 변형은 실행 데이터와 두 카드 UI에 연결했다. 공유 증폭/연마의 전체 참여 인술 갱신·공유 횟수·후보 중복 방지 처리도 구현했다. 실제 공유 카드는 상대 인술이 아직 실행 목록에 없어 활성화하지 않았다. 영구 성장 실제 레코드 연결과 Unity 통합 검증은 여전히 남아 있다.
